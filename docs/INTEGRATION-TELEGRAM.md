# Подключение Telegram-бота

Каркас готов и запускается. Ниже — что сделать, чтобы бот заговорил.

## Шаг 1. Создать бота

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username.
2. Полученный токен положить в `.env`:

```
TELEGRAM_BOT_TOKEN="123456:AA..."
TELEGRAM_MODE="polling"
```

3. Запустить `npm run dev`. В логе появится
   `Telegram-бот запущен в режиме polling` с username бота.

Команды регистрируются в меню автоматически при старте (`setMyCommands`).

## Шаг 2. Проверить

В чате с ботом: `/start`, `/help`, `/lang`. Они работают уже сейчас.

Команды данных (`/digest`, `/sales`, `/stocks`, `/problems`, `/reviews`,
`/stores`) отвечают честной заглушкой: «появится, когда подключим коннектор».
Это сделано намеренно — показать продавцу выдуманные цифры хуже, чем сказать,
что источник не подключён.

## Шаг 3. Прод: webhook вместо polling

Polling не годится для прода: два процесса с одним токеном конфликтуют, а при
рестарте теряется часть апдейтов.

```
TELEGRAM_MODE="webhook"
APP_URL="https://ваш-домен"
TELEGRAM_WEBHOOK_SECRET="<длинная случайная строка>"
```

При старте приложение само вызовет `setWebhook` на `APP_URL/api/telegram/webhook`
с этим секретом. Сервер сверяет заголовок `X-Telegram-Bot-Api-Secret-Token` до
разбора тела запроса и отбрасывает чужие запросы — эндпоинт публичный.

Требования Telegram: HTTPS с валидным сертификатом, порт 443/80/88/8443.

Проверка: `GET /api/platform/health` → `telegram.enabled: true`, `mode: "webhook"`.

## Шаг 4. Привязка магазина (ещё не реализовано)

Задуманная схема:

1. В веб-интерфейсе продавец нажимает «Подключить Telegram» → сервер создаёт
   одноразовый код в `telegram_link_codes` со сроком жизни (10–15 минут).
2. Продавец отправляет боту `/link КОД`.
3. Бот находит код, проверяет срок и то, что он не использован, создаёт запись
   в `telegram_accounts` с `organization_id` и `active_store_id`, помечает код
   использованным.

Почему через код, а не через номер телефона: номер не доказывает права на
магазин, а код выдаётся уже аутентифицированному пользователю в вебе.

Обработчик — `server/telegram/commands.ts`, команда `link` (сейчас заглушка).
Таблицы уже есть в схеме.

## Шаг 5. Алерты

Ключи сообщений готовы в `server/i18n/locales/*`: падение позиций, риск
out-of-stock, демпинг конкурента, негативный отзыв.

Что нужно дописать: сервис рассылки, который берёт из БД подписчиков
(`telegram_accounts.alerts_enabled`) и шлёт им сообщение на их локали.

Ограничения Telegram, которые надо заложить сразу:

- около 30 сообщений в секунду суммарно, около 1 сообщения в секунду в один чат;
- при массовой рассылке ставить очередь, а не цикл `for`;
- ошибка 403 «bot was blocked by the user» — не сбой, а сигнал выключить
  `alerts_enabled` для этого аккаунта.

## Отладка

- Локально без публичного URL — только polling.
- Если бот молчит: проверить, что `TELEGRAM_MODE` не `disabled` (значение по
  умолчанию), и что в логе нет `Ошибка Telegram API`.
- Ошибка `409 Conflict` — где-то запущен второй процесс с тем же токеном.
- Для разработки удобно завести отдельного тестового бота, чтобы не трогать
  боевого.
