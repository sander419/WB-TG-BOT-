# Что происходит в этом проекте

Вводная для любого, кто подключается к работе: человека или агента.
Прочитать целиком до первой правки — это дешевле, чем разбирать последствия.

Обновлено 2026-09-07.

## В одном абзаце

CommerceOS — платформа управления продажами на маркетплейсах (Wildberries,
Ozon, Shopify, закупка на китайских площадках) с Telegram-ботом. Проект
задуман международным и мультиарендным. **Ни один маркетплейс пока
не подключён** — ждём боевой токен продавца. Всё остальное построено вокруг
этого момента: когда токен появится, подключение должно занять минуты,
а не дни.

## Осторожно: репозиторий обманчив

Название репозитория — `WB-TG-BOT-`, но исходно внутри не было ни бота,
ни WB API. Проект пришёл раскладкой из Google AI Studio: 26 тыс. строк
фронтенда, работающих на захардкоженных данных `src/data/mockStore.ts`.
Демо-эндпоинт `/api/health` рапортовал `wb: ACTIVE` строкой, вписанной в код.

Этот демо-слой **до сих пор на месте** и до сих пор показывает выдуманные
цифры. Он будет удалён на этапе 3 дорожной карты. Пока он есть:

- не принимайте его данные за реальные;
- не развивайте его;
- реальная работа идёт в `server/`.

## Что реально работает

| Подсистема | Где | Состояние |
|---|---|---|
| Ядро (ошибки, логи, деньги, шифрование, HTTP, лимитер) | `server/core/` | Готово, покрыто тестами |
| Контракт площадок | `server/connectors/types.ts` | Готово — **главный шов проекта** |
| Коннектор WB | `server/connectors/wildberries/` | Чтение написано, **не проверено токеном** |
| Хранилище: 17 таблиц, 3 миграции | `server/db/` | Проверено на живом Postgres |
| Очередь и воркер синхронизации | `server/sync/` | Написано, вживую не гонялось |
| Расчёты, диагностика, алерты | `server/analytics/` | Готово, чистые функции + тесты |
| Telegram-бот | `server/telegram/` | Команды считают по БД |
| Вход, сессии, роли | `server/services/auth.ts`, `server/http/` | Готово, проверено через HTTP |
| Страница настройки | `/setup` | Готово, проверено в браузере |
| Продакшен-образ | `Dockerfile`, `docker-compose.prod.yml` | Написано, **образ не собирался** |

Цифры: ~8.9 тыс. строк backend, 2.8 тыс. строк тестов, 208 тестов
(69 интеграционных на живой БД), 26 тыс. строк демо-фронтенда.

## Единственный блокер

**Боевой токен Wildberries.** Без него нельзя:

- сверить 20 путей API, помеченных `verified: false` в `endpoints.ts`;
- проверить формы ответов в `schemas.ts`;
- прогнать настоящую синхронизацию;
- убедиться, что цифры сходятся с личным кабинетом.

Подтверждено запросами только это: хосты `common-api.wildberries.ru`
и `content-api.wildberries.ru` живы, путь `/ping` существует и **без токена
отвечает 401, а не 200**.

## Правила проекта

Нарушение любого из них — повод отклонить правку.

1. **Деньги — целые минорные единицы плюс код валюты.** Никаких float.
   `server/core/money.ts`.
2. **Время в БД — UTC.** Локальные сутки считаются по таймзоне магазина:
   у витрины в Москве и в Гуанчжоу «вчера» разное.
3. **Цифры считает код, а не языковая модель.** Модель формулирует, но
   не считает. Весь счёт — в `server/analytics/`, покрыт тестами.
4. **Данных нет — так и сказать.** Не показывать правдоподобные выдуманные
   числа. Пустой массив вместо «не реализовано» — запрещён: он выглядит
   как «товаров нет» и уводит отладку в сторону.
5. **Секреты продавцов шифруются перед записью** и не попадают в логи.
   Расшифровка ровно в одном месте — `db/repositories/stores.ts`.
6. **Запись в маркетплейс по умолчанию запрещена** (`ALLOW_MARKETPLACE_WRITES=false`).
7. **Организация берётся из сессии, а не из запроса.** Забытый фильтр
   по `organization_id` — это чужие продажи в чужом отчёте.

## Чего не делать

Список написан по реальным происшествиям, а не из вежливости.

- **Не писать код, не открыв `docs/ARCHITECTURE.md` и дерево `server/`.**
  Сгенерированный вслепую PR предлагал winston вместо уже работающего pino,
  свой лимитер вместо существующего, и обращался к схеме `src/db`, которой
  в проекте нет. Закрыт без слияния.
- **Не коммитить `node_modules`.** В том же PR их приехало 19 639 файлов.
- **Не заводить вторую реализацию** логгера, лимитера, HTTP-клиента, расчёта
  денег. Они есть, они покрыты тестами.
- **Не трогать `.gitignore` и shell-скрипты без нужды.** Концы строк
  зафиксированы в `.gitattributes`: `entrypoint.sh` с CRLF в контейнере даёт
  «no such file or directory» про интерпретатор и ищется часами.
- **Не добавлять зависимость там, где хватает стандартной библиотеки.**
  Пароли на scrypt, разбор куки, лимитер — свои, намеренно.
- **Не помечать пути WB как проверенные, не сделав запрос.**

## Как запустить и убедиться, что всё цело

```bash
npm install
cp .env.example .env          # DATABASE_URL и npm run gen:key
npm run db:migrate
npm run lint && npm test && npm run build
npm run smoke:db              # сквозной прогон слоя данных
npm run dev                   # http://localhost:3000/setup
```

Postgres 17 стоит локально (`winget`), база `commerceos`.
⚠️ У суперпользователя `postgres` пароль по умолчанию от установщика —
порт 5432 наружу не выставлять.

Что настроено в конкретной установке, честно показывает
`GET /api/platform/health`: он не врёт про «всё ACTIVE», а перечисляет
недостающие переменные (подробности — после входа).

## Известные риски

- **Регистрация открыта для всех** — приглашений нет, любой создаёт себе
  организацию. Закрыть до первых внешних пользователей.
- **Демо-фронтенд показывает выдуманные данные.** `/setup` об этом
  предупреждает, но человек, открывший главную, предупреждения не увидит.
- **Продакшен-образ не собирался** — Docker на машине разработки не установлен.
  Первая `docker build` может потребовать правок.
- **Лимитеры и сессионные отметки живут в памяти процесса.** При двух
  инстансах лимит площадки удвоится. Переносить в Redis вместе с выносом
  воркера.

## Открытые вопросы к владельцу

Влияют на схему БД, поэтому дешевле решить до наполнения данными.

1. **Одна страна или сразу несколько** — нужны ли юридические поля (НДС,
   режим налогообложения) уже сейчас.
2. **Размерные линейки WB** — если магазин торгует размерами, нужна отдельная
   сущность варианта товара. Сейчас модель товара плоская.
3. **Кто хозяин цены** — только человек через подтверждение или правило
   в заданном коридоре. Ответ определяет объём этапа записи.
