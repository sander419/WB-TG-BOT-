# 📋 Pre-Launch Checklist

Используйте этот чек-лист перед первым запуском в продакшене.

## 1. Безопасность и Конфигурация
- [ ] Скопировать `.env.example` в `.env`
- [ ] Сменить все пароли `CHANGE_ME` на сложные уникальные значения
- [ ] Сгенерировать новый `JWT_SECRET` (минимум 32 символа)
- [ ] Проверить, что `.env` добавлен в `.gitignore`

## 2. База Данных
- [ ] Убедиться, что PostgreSQL запущен и доступен
- [ ] Создать базу данных и пользователя (если не делается автоматически)
- [ ] Запустить миграции: `npm run db:migrate`
- [ ] Проверить подключение через DBeaver или pgAdmin

## 3. Внешние Сервисы
- [ ] **Wildberries**: 
    - [ ] Получить актуальный API токен в личном кабинете селлера
    - [ ] Проверить права токена (статистика, контент, заказы)
- [ ] **Telegram**:
    - [ ] Создать бота через @BotFather
    - [ ] Получить токен бота
    - [ ] Узнать свой Chat ID и добавить в конфиг
    - [ ] Нажать `/start` в боте, чтобы активировать его

## 4. Инфраструктура (Docker)
- [ ] Проверить `docker-compose.prod.yml` на соответствие версий образов
- [ ] Убедиться, что порты не заняты другими сервисами
- [ ] Протестировать сборку: `docker-compose -f docker-compose.prod.yml build`
- [ ] Проверить health-checkи контейнеров после запуска

## 5. Тестирование
- [ ] Запустить автотесты: `npm test`
- [ ] Проверить ручные сценарии:
    - [ ] Получение статистики WB
    - [ ] Отправка уведомления в Telegram
    - [ ] Корректное отображение дашборда
- [ ] Проверить логи на наличие ошибок (особенно при старте)

## 6. Мониторинг (Post-Launch)
- [ ] Настроить сбор логов (ELK, Loki или простой вывод в файл)
- [ ] Настроить алерты при падении сервиса (Uptime Kuma, Pingdom)
- [ ] Проверить потребление памяти и CPU под нагрузкой
